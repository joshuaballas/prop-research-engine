# API Endpoints

Base URL for local examples:

```text
http://localhost:5299
```

Most endpoints below are debug/admin endpoints. They are available by default in Development. Outside Development, `/api/debug/*` requires `DebugAdmin` to be enabled and may require `X-Debug-Admin-Key`.

Legend:

- Writes: creates or updates database rows.
- External API: calls a provider outside the app.
- Credits: spends The Odds API credits.

## PrizePicks Through The Odds API DFS

PrizePicks and Underdog are supported as The Odds API DFS bookmakers through region `us_dfs` with bookmaker keys `prizepicks` and `underdog`. DraftKings Pick6 and Betr Picks use `pick6` and `betr_us_dfs`. Direct provider scrapers should not feed customer-facing market rows.

## The Odds API MLB

The Odds API is a data provider/aggregator. Persist actual bookmakers as platforms, such as DraftKings, FanDuel, BetMGM, or Bovada. Store provider context in metadata as The Odds API.

## Production-Safe Market Read Endpoints

These routes are intended for the customer frontend/public surface. They never call The Odds API, never call direct Underdog, and never write rows. They read the latest persisted odds, prediction, line-shopping, top-pick, and refresh metadata populated by controlled backend refreshes.

Prefer `/api/markets/*` for frontend work. `/api/mlb/*` remains as compatibility wrappers around the same implementation with `sport=MLB`. Do not add separate duplicated endpoint families such as `/api/nba/*` or `/api/ufc/*` unless there is a specific reason; add new sports behind `/api/markets/*` with sport filters instead.

Current limitation: MLB persisted market reads include grading/prediction support. Soccer / World Cup persisted market reads are available as sportsbook context, with guarded backend prediction/grading support only for Goals, Assists, Shots, and Shots On Target when `SoccerPredictions:Enabled`, `SoccerGrading:Enabled`, and `SoccerTopPicks:Enabled` are explicitly enabled. When `sport` is omitted, `/api/markets/*` returns MLB data by default. Use `sport=SOCCER&competition=World Cup` for persisted World Cup context. Soccer Entry Builder actionability remains disabled.

Shared recommendation contract: `selectedSideProbability` is always the hit probability for the selected side/outcome, and `modelProbabilityOver` / `modelProbabilityUnder` are side-specific probabilities when the market has Over/Under sides. Recommendation-facing `recommendationProjection` / `displayProjection` must be aligned to the same probability basis, or the row must mark non-aligned projections as context only. MLB exposes `recentWeightedProjection` as context for season/last10/last5 trend projection; it is not the recommendation projection. Sportsbook EV is true expected value for the exact bet, `P(win) * decimalOdds - 1`, using selected-side probability and real sportsbook price. Sportsbook rows expose `rawSelectedSideProbability`, `calibratedSelectedSideProbability`, `probabilityCalibrationMethod`, `rawExpectedValue`, `calibratedExpectedValue`, `displayExpectedValue`, `evCalibrationMethod`, and `evSuppressedReason`; public recommendation areas should display only unsuppressed `displayExpectedValue` when it is available. DFS rows set `showExpectedValue=false` unless a separate DFS payout model is explicitly supported. `projectionProbabilityConflict`, `recentWeightedProjectionProbabilityConflict`, lifecycle blocks, missing side/line, missing history, missing supported prop mapping, or insufficient reliability must not be promoted as `isCandidate=true`, `isRecommendation=true`, or Top Picks. `recommendationActionableForUser` means the row is a real recommendation; `entryActionableForUser` means it can be added to Entry Builder. Sportsbook recommendations can be recommendation-actionable while remaining non-entry-actionable.

Top Picks use `TopPicksModel:ActiveModel`, default `LikelyHitV1`. Likely-Hit v1 ranks by selected-side hit chance, reliability, sample quality, lifecycle validity, supported prop mapping, and Balanced-mode payout quality. EV is not the primary Top Picks gate; sportsbook rows still require real price context, but a row can remain a recommendation with display EV hidden or suppressed. Default Balanced mode blocks sportsbook Top Picks with selected-line American odds worse than `TopPicksModel:SportsbookBalancedMaxFavoriteAmericanOdds`, default `-300`, and underdog/longshot prices above `TopPicksModel:SportsbookBalancedMaxUnderdogAmericanOdds`, default `+250`; exactly `-300` and `+250` pass the price-window gate, subject to the other hit-chance, reliability, lifecycle, and suspicious market-gap gates. Sportsbook Balanced model/inventory/replay enrichment still uses `TopPicksModel:SportsbookBalancedTargetMinHitChance`, default `0.60`; rejected rows below that lower modelability floor expose `minimumHitChanceGate`, `minimumHitChanceRequired`, `hitChanceGatePassed`, and `BelowBalancedMinimumHitChance`. Public sportsbook Top Picks apply the stricter replay-backed `TopPicksModel:SportsbookBalancedPublicMinimumHitChance`, default `0.65`, after uncertainty haircut and selected-line choice; rows in the 60-65% band remain visible in Line Shopping, Prop Scanner, and replay diagnostics, but are blocked from public Top Picks with `BelowSportsbookPublicTopPickHitChance`. Current Likely-Hit v1 public recommendations are stamped with `TopPicksModel:CurrentModelEra`, default `LikelyHitV1_SportsbookBalanced_65Plus_ConsistencyGuarded`, so public Performance can quarantine older/missing-era recommendations by default. MLB public Top Picks evaluate persisted selected-side `prop_results` history before promotion and fail closed when a high displayed hit chance severely contradicts the recent selected-side chart window or side/line averages. Public/debug rows expose `publicTopPickMinimumHitChance`, `publicTopPickHitChanceGatePassed`, `selectedSideHistoryConsistencyGuardApplied`, `selectedSideHistoryConsistencyGuardPassed`, `selectedSideChartHitRate`, `selectedSideChartSampleSize`, `selectedSideRecent5Average`, `selectedSideRecent10Average`, `selectedSideSeasonAverage`, and consistency conflict codes where the Likely-Hit audit metadata is applied. Public Top Picks rows include additive model fields such as `modelVersion`, `modelEra`, `probabilityModelVersion`, `recommendationContractVersion`, `hitChance`, `topPickScore`, `reliabilityScore`, `effectiveSampleSize`, `payoutQualityScore`, `sweetSpotScore`, `hitChanceScore`, `balancedLineUtility`, `priceGateStatus`, `priceGateReason`, `playablePriceEligible`, `favoritePriceCeiling`, `underdogPriceCeiling`, `suspiciousMarketGap`, `marketGap`, `topPickQualityEligible`, `lineUtilityScore`, `alternateLineGroupKey`, `selectedRecommendedLine`, `balancedLineSelectionReason`, `recentModifier`, `marketCalibrationAdjustment`, `uncertaintyPenalty`, and `fatalConflictCodes`. Line Shopping and Prop Scanner remain full market-access inventory pages and must not be filtered or blocked by Top Picks model promotion state.
