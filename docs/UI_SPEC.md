# UI Design Specification

## Design Goals

The application should feel like a premium sports analytics platform.

Inspiration:

- OddsJam
- PrizePicks
- Underdog Fantasy
- DraftKings Sportsbook

Do not copy any design exactly.

Use them only as inspiration.

---

# Theme

Dark Mode First

Professional

Modern

Data Dense

Fast To Scan

Desktop First

Mobile Responsive

---

# Avoid

- Generic Bootstrap styling
- Enterprise software appearance
- Large empty whitespace
- Default Material UI appearance
- Outdated admin dashboard designs

---

# Visual Style

Background:

Dark charcoal

Cards:

Slightly lighter than background

Positive EV:

Green

Negative EV:

Red

High Confidence:

Gold

Information:

White and light gray

---

# Navigation

Left Sidebar Navigation

Items:

- Dashboard
- Props
- Line Movement
- Best Plays
- Parlay Builder
- Settings

---

# Dashboard

Top Summary Cards:

- Active Props
- Best Plays
- Recommended Entries
- Significant Movers

Main Content:

- Best Plays Table
- Recent Line Movement
- Recommended Entries
- Trending Props

Display:

- Player

- Sport
- Prop Type
- Platform
- Current Line

- Edge
- Last Movement

- Search
- Filtering
- Sorting

# Prop Details Page

Display:

- Prop Information

- Platform Comparisons

- Related Props

# Best Plays Page

Display:

- Highest Confidence Plays
- Highest EV Plays

---

# Parlay Builder

Display:

- Suggested Entries
- Correlation Analysis
- Probability Estimates
- Expected Value

Allow:

- Manual Entry Building
- Automatic Entry Generation

---

# Charts

Use charts wherever possible.

Examples:

- Line Movement
- Historical Trends
- Correlation Visualizations
- Confidence History

---

# UX Requirements

Must feel like a production SaaS application.

Must not feel like a developer tool.

Must not feel like an internal business application.

Focus on:

- Clean layouts
- Clear hierarchy
- Fast readability
- Modern interactions
- Professional polish

---

# Frontend Instructions

Before generating React code:

1. Create wireframes.
2. Create page layouts.
3. Create component hierarchy.
4. Present designs for approval.

Do not immediately generate frontend code.

Wait for design approval first.
